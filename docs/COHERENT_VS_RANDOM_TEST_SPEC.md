# Technical specification: coherent vs arbitrary-node repertoire experiment

Status: **proposed implementation specification; not yet executed**
Date: 2026-11-02
Repository: `EnluniLabs/static-agent-training`
Priority: central structural hypothesis test
Related: [future work](../FUTURE_WORK.md), [implementation](IMPLEMENTATION.md), [environment](../ENVIRONMENT_INTERFACE.md), [bias audit](BIAS_AUDIT.md).

## 1. Objective and falsifiable claim

Test whether an inherited repertoire generated by lambda-calculus development
improves acquisition of useful behavior and predictions compared with an
arbitrary-node repertoire under the **same lifetime learning algorithm**.

Primary contrast: **COHERENT** (existing certified lambda-derived successor
graph) vs **RANDOM_CHAIN** (anonymous nodes with arbitrary, fixed successor
links). This is *not* an anchor-free or ordinary neural-network baseline.
Both arms keep empirical expectation updates and delayed structural
compatibility updates enabled. The latter must target the actual successor
of the active arm.

Hypothesis: coherent development provides a more useful inductive organization
of candidate interpretations than arbitrary chains, making learning more
sample-efficient. This is an empirical hypothesis, not a claim that lambda
terms are evaluated during lifetime learning, that every lambda graph is
advantageous, or that the physical universe has been proved computationally
coherent.

A single chain `A -> B -> C` is behaviorally isomorphic to `1 -> 2 -> 3`
under a consistent renaming and matched weights. The possible advantage must
arise from differences in the **ensemble of developed repertoires**, including
their topology and distribution under evolutionary search. Do not treat
renaming a lambda graph as a meaningful random-structure treatment.

## 2. Current implementation to preserve

As documented in `docs/IMPLEMENTATION.md` and `ENVIRONMENT_INTERFACE.md`:
- Current/goal categorical embedding rows combine to sample an entry pair.
- The agent follows a stored successor edge, then samples one of nine moves
  or 41 absolute-position expectations from the successor's output logits.
- Tested, explicitly emitted expectations update the emitting pair's
  expectation logits by conditional cross entropy (default rate 0.05).
- Empirical revision marks the source pair; on a later encounter, its
  most-supported expectation's observation embedding is checked against the
  fixed successor and may receive a local boost (threshold 0.1, rate 0.05).
- No lifetime lambda reduction. No direct movement-reward gradient.
- Evolution selects on training task success; assessment is frozen. Learned
  lifetime weights are not inherited by default.
- Number line [-20,20], hard walls, moves -5,-3,-2,-1,0,1,2,3,5,
  12-move limit, 16-output-per-observation limit; uniform valid start/goal
  pairs, recorded token permutation, speciation off by default.

Do **not** modify the sensory interface, prediction vocabulary, error formulas,
action policy, goal information, wall rules, or task distribution in this test.

## 3. Treatment design

### 3.1 COHERENT

Use the current `Species` / `genome.develop` pipeline. An initial ordered
pair of closed lambda terms and its budget generate repertoire entries and
certified successors via completed `NF(B A)` computations. Retain the
existing shared-pair merges, cycles, missing successors, development budgets,
reproduction, and weight mutation semantics. Save provenance and costs.

### 3.2 RANDOM_CHAIN: minimal first control

Create an alternate **repertoire generator**, not an alternate learner.
Produce opaque, stable node IDs and fixed directed successor links forming
one or more chains. No lambda terms, beta reduction, normal-form certification,
or physical/goal knowledge may be used to choose links.

For a paired coherent genotype, take the **per-seed-chain length profile**
(number of entries along each originating development path, before unique-pair
deduplication) and independently create anonymous chains with those lengths.
Assign unique random IDs from a seeded namespace, not values that encode
position, goal, movement, or expected observation. By default, do not merge
nodes across chains and do not add cycles. Each nonterminal node has one
successor; final nodes have none. If coherent chains have repeated-pair cycles
or merges, record these as **unmatched topology**, not as a random-chain
failure or an equivalent matched control.

Because deduplication and merges can make coherent unique-node count differ
from the sum of path lengths, a chain-length match **does not guarantee equal
unique repertoire size**. Report both, and add a separate size-matched
random-chain variant if the mismatch is material. Size-matched chains should
allocate the coherent unique-node count across chains with a deterministic
seeded rule, preserving at least one node per chain when feasible. Never
silently discard coherent nodes or pretend both constraints can always hold.

A chain generator must not call the lambda reducer or copy coherent successor
edges. Its only use of coherent metadata is **experimental budget matching**
(e.g. sizes/lengths); explicitly label this as a conditioned control. Also
provide an independent random-size distribution control if matching to the
coherent profile creates a concern about information leakage. Neither control
uses environment feedback to construct its graph.

### 3.3 RANDOM_GRAPH: follow-up attribution control

If the initial contrast shows a difference, add random graphs conditioned on
the coherent repertoire's **observable topology statistics**, to the extent
feasible: unique-node count, number of edges, indegree distribution,
terminal fraction, components, cycles, merge counts, and path-length profile.
Generate links without evaluating lambda terms and without reproducing the
coherent adjacency list. Use independent rewiring / constrained sampling and
record exact statistics and matching failures.

A topology-identical, label-permuted coherent graph is an **isomorphism
sanity test**, not evidence for lambda-specific benefits. If matching all
relevant graph properties makes the structures behaviorally indistinguishable,
report that limitation; the current lifetime learner cannot access term
semantics beyond the successor graph.

## 4. Integration contract

Implement a generator strategy at the **repertoire/development boundary**.
The downstream `Repertoire`, `InheritedMappings`, `Agent`, environment,
learning, and fitness interfaces should be unchanged wherever possible.

Suggested experiment config (names are proposals; map to existing CLI style):

```yaml
experiment: coherent_vs_random_repertoire
repertoire_mode: coherent | random_chain | random_graph
random_matching: path_lengths | unique_nodes | topology_stats
learning: empirical_and_structural
inherit_lifetime: false
speciation: false
environment: number_line_hard_wall
seed: 42
```

Generator metadata should include schema version, arm, random seed, node IDs,
successor map, component/chain provenance, terminal status, matching target,
actual graph statistics, and a stable content hash. The existing repertoire
serializer must accept anonymous nodes **without fabricating lambda ASTs or
certification**; if it cannot, introduce a clearly typed alternate schema and
a validated adapter. Do not weaken coherent certification invariants.

**Evolutionary fairness:** a one-off randomization of a fixed coherent
population is a useful fixed-genotype diagnostic, but not a fair full
evolutionary comparison. Random animals need their own reproducible
genotype and structural mutation/redevelopment operators: node insertion,
deletion, chain extension/truncation and/or rewiring according to the chosen
arm, with explicit rates and computational budgets. Map surviving node IDs
to inherited weights and initialize new IDs with the existing seeded
initialization protocol. Do not use coherent term mutations in the random
arm or grant it unreported extra mutation opportunities.

Exact genotype-level pairing across different genotype spaces is impossible.
Match initial repertoire-size distributions, mapping initialization law,
population and selection settings, total evaluation opportunities, and
mutation *resource budgets*; record residual differences. Compare fixed
repertoires first to isolate lifetime learning, then separately compare
full evolutionary adaptation. Report generation cost as an outcome; equal
wall-clock time and equal evaluation count are different comparisons.

## 5. Staged experimental procedure

### Stage 0: parity and feasibility (no performance claims)

1. Construct small hand-auditable coherent and random repertoires.
2. Verify both traverse, emit, receive feedback, and update through exactly
   the same agent code. Structural checks must use each arm's own successor.
3. Test an isomorphic graph relabeling with correspondingly permuted weights
   and controlled RNG; outputs, updates, and fitness should match.
4. Check anonymous-node serialization, replay, hashing, mutation, and
   terminal-edge behavior. Verify Python and optional native CPU/CUDA
   parity **before** trusting accelerated comparisons.
5. Record graph sizes and compute costs. Never silently skip a backend or
   reinterpret failed reduction as a random-node edge.

### Stage 1: fixed-repertoire lifetime-learning comparison

Use independently sampled coherent repertoires and corresponding random-chain
controls. Freeze both successor graphs and inherited weights. For each
repertoire, run matched ordered episode streams with learning enabled,
preserving learned weights across episodes as currently implemented. Assess
on separate frozen copies at checkpoints along the exposure curve.

Include two diagnostics per repertoire type:
- **Structural-off:** empirical learning enabled, structural correction off.
- **All-learning-off:** neither update enabled.

These are diagnostics, not substitutes for the main coherent-vs-random
comparison with **both rules on**. If disabling only structural learning is
not currently supported, implement an explicit, tested switch without
altering the update formula or conflating it with `learn=False` (which
disables both).

Use matched tasks, token encodings, parameter initialization distributions,
episode budgets, and evaluation samples. Separate stochastic seeds for graph
generation, weight initialization, task lists, traversal, output, and
mutation; record them. Common random numbers are desirable where feasible
but cannot guarantee identical sampled trajectories on different graphs.

### Stage 2: evolutionary comparison

After Stage 1 validates the random genotype/mutation machinery, evolve
independent populations per arm. Freeze a complete manifest **before** final
runs. Suggested initial pilot (not an established power calculation):
- 3 paired experiment seeds for debugging/variance estimation;
- 256 animals per arm, 20 generations;
- 100 training and 200 frozen assessment episodes per animal;
- 2,000 fresh shared final test episodes for each training-selected champion;
- hard walls, uniform valid pairs, no speciation, lifetime inheritance off.

Use pilot variance to select an adequately powered confirmatory number of
independent runs; do not claim the three-seed pilot is definitive. Training
fitness alone selects parents/champions. Reuse the same task draws within a
paired seed; reserve untouched final test draws until design is frozen.
Run arms separately without interrupting current active studies. Label
checkpoint versions and forbid cross-arm resume/config coercion.

### Stage 3: environment adequacy gate

The number line is the **first** environment, not a guaranteed discriminating
test. Before interpreting a null difference, inspect whether animals actually
exercise enough structure and whether structural learning changes anything.
If use is low, design a second environment that demands reusable relationships,
predeclare its interface and success criteria, and rerun both arms unchanged
except for the shared environment adapter. Do not select a new environment
solely because it favors one arm.

## 6. Required instrumentation

Emit per-animal and per-episode counters (with optional detailed traces):

- Repertoire unique-node count, total edges, terminals, components, longest
  paths, chain length distribution, merges, branching/indegree, cycles.
- Unique selected entry nodes, traversed successor nodes, **distinct exercised
  edges**, repeated traversals, and fraction of available nodes/edges used.
- Distinguish a selected entry from a traversed edge and an output-emitting
  node. Record edge coverage by chain/component and multi-edge trajectories.
- Explicit predictions emitted/tested/correct/expired; conditional
  prediction loss and calibrated accuracy where estimable.
- Empirical update counts and absolute/squared logit-change magnitudes.
- Structural check eligibility, checks run, below-threshold conflicts,
  update counts and magnitudes, revisits, and lag after empirical revision.
- Frozen task success, moves to success, output counts, no-success reasons
  (including missing successor), per-goal and per-distance results.
- Graph-generation cost, training/evaluation runtime, parameter counts,
  replay seeds, and graph/genotype hashes.

Compute utilization at **node, edge, and connected-substructure** levels.
High utilization does not prove causal dependence. Use the structural-off
counterfactual to measure whether the correction mechanism actually changes
learning or performance. Current structural correction is local to a
successor compatibility check; do not assume multi-edge propagation without
observing it.

Store aggregate tables in machine-readable JSON/CSV and bounded trace
samples, not only terminal charts. Use schema versioning and clear
`arm`/`mode` fields throughout logs, checkpoints, and reports.

## 7. Primary outcomes and analysis

**Primary metric:** area under the **frozen held-out success vs. lifetime
training-interactions** curve in Stage 1, over a predeclared fixed budget
and checkpoint schedule. This directly tests sample efficiency rather than
only eventual evolutionary fitness. Predeclare integration/normalization
method and equal interaction budgets. If learning rarely updates, explicitly
report this limitation.

**Secondary metrics:** frozen conditional prediction loss and accuracy,
final held-out success, structural-on/off difference, adaptation slope,
repertoire coverage, missing-edge termination, and compute cost. Stage 2
reports training-selected champions' fresh-test success and population
statistics separately; it is not pooled with Stage 1.

Treat independent repertoire draws/evolutionary runs as the statistical units,
not episodes or nodes. Report per-seed paired differences, uncertainty
intervals, effect sizes, and variation across graph instances. Predeclare
the comparison family and avoid claiming significance from repeatedly
inspected pilot results. Plot learning curves with uncertainty bands and
utilization/structural-update distributions.

Interpretation matrix:
- Coherent > random, with meaningful structural dependence: supports a
  useful **lambda-development-induced structural bias** in this task.
- Coherent > random but topology differs: does **not** isolate specifically
  lambda semantics; test RANDOM_GRAPH.
- Coherent ~= random with negligible structural engagement: **uninformative**
  about the broader hypothesis; the task or learner may not exercise it.
- Coherent ~= random with substantial engagement and adequate precision:
  negative evidence for an advantage **under these conditions**.
- Random > coherent: evidence against the chosen coherent generator as a
  better bias **under these conditions**.

No outcome alone proves physical reality is lambda-computational, that a
learned prediction is a full Popperian explanation, or that constraints
necessarily reduce the effective search space.

## 8. Acceptance criteria / deliverables

Implementation is ready for a pilot only when:
1. Existing coherent behavior and historical replay tests still pass.
2. Random nodes cannot leak lambda terms, target positions, distances, or
   privileged environment values into the agent.
3. Both arms use the identical empirical/structural update code paths and
   comparable interfaces; successor targets are arm-specific.
4. Graph and mutation provenance are reproducible from saved manifests.
5. Isomorphic renaming passes its equivalence test.
6. Structural-off and both-off diagnostics are independently testable.
7. Native backends match Python reference traces within documented numerical
   tolerances, or the pilot explicitly uses Python only.
8. Frozen assessment cannot update weights or affect parent/champion selection.
9. Utilization and structural-dependence metrics are present in outputs.
10. Run instructions, smoke-test commands, and exact configs are documented
    when code is implemented; this specification alone is not an executable test.

**Out of scope:** generalized bitwise interface, learnable successor links,
repertoire growth during a lifetime, alternate empirical error rules, and
changing the number-line task before the adequacy diagnostics are collected.

## 9. Key risk

The lifetime agent sees only anonymous nodes and successor links. Any two
repertoires that are graph-isomorphic, with corresponding mappings, are
behaviorally equivalent to it. Therefore the experiment can measure whether
**the distributions of graphs generated by lambda development** make learning
easier than arbitrary-node graph distributions. It cannot attribute a
difference to an invisible metaphysical property of lambda terms after those
terms have been stripped away. That limitation should guide both the controls
and the claims.
